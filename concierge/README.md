# Concierge CLI (Python, until Milestone 1)

Used in weeks 1–6 to hand-build packs for design partners while we test whether people pay. Frozen after M1: bug fixes only, each with a new vector so the Go code inherits it.

- `verify.py`: offline verifier for one or more packs, oldest first. Checks signature, subject digest, chain and the disclosed trace's Merkle proof.
  `python3 concierge/verify.py spec/vectors/test-public-key.pem spec/vectors/pass/*.dsse.json`
- `evidencepack.py ingest` (C-1): OTLP JSON dumps (one export per line, or one document) or Langfuse exports (JSON array or CSV) to hourly aggregates in the batch `metrics` shape, plus a leaves file of salted Merkle leaves (one hex hash per line) for the pack commitment. Content is never read; trace IDs leave only as salted leaves.
  `PLUMBLINE_SALT_SECRET=... python3 concierge/evidencepack.py ingest --source otlp --out aggregates.json --leaves leaves.txt export.jsonl`
  Attribute names for PII, guardrails, prompt versions, tool approval and escalation default to `plumbline.*` (see `ingest.DEFAULT_ATTRIBUTES` and D-020); pass `--attributes partner.json` to map a partner's own names or change the anomaly thresholds.
- `evidencepack.py evaluate` (C-2): aggregates plus provider usage CSVs and the change, incident and eval registers to the ten objectives (`evaluation.json`), with coverage, lineage and limitations ready for the pack. Semantics in D-021.
  `python3 concierge/evidencepack.py evaluate --system system.json --aggregates aggregates.json --usage usage.csv --changes changes.csv --incidents incidents.csv --evals evals.csv --out evaluation.json`
  Formats: see `testdata/partner-month/` (a hand-calculated month) and D-021. Usage CSV: `provider,model,region,start,end,input_tokens,output_tokens,requests`, provider IDs as in telemetry.
- `canon.py`: RFC 8785 canonical JSON matching Go and the browser verifier (used for hashes and, in C-3, signing).
- `evidencepack.py sign` (C-3): evaluation + leaves to a signed pack, chained to `--prev`. Checks the predicate against `spec/pack.schema.json`, requires canonical JSON and verifies its own signature before writing (D-022).
  `python3 concierge/evidencepack.py sign --evaluation evaluation.json --leaves leaves.txt --pack-id WRN-RS-0002 --prev WRN-RS-0001.dsse.json --kid <kid> --key key.pem --out WRN-RS-0002.dsse.json`
  For KMS use `--kms-key-id <arn>` instead of `--key` (needs `pip install boto3` and AWS credentials). `--disclose <trace id>` reveals one trace (needs the salt secret); `--jwks-out jwks.json` writes the public key for verifiers.
- `evidencepack.py share` (C-4): publish a verified pack behind an unguessable link on a static site in the same shape as the future API (D-023). Prints the link once; the share log keeps only the token's SHA-256.
  `python3 concierge/evidencepack.py share --pack WRN-RS-0002.dsse.json --prev WRN-RS-0001.dsse.json --jwks jwks.json --site-dir site --base-url https://verify.example --verifier "Bank X"`
  Then publish `site/` (for example to Cloudflare Pages). `evidencepack.py unshare --site-dir site --token-sha256 <from the log>` revokes a link; publish again to take it down.
- Tests: `make concierge-test` (`python3 -m unittest discover -s concierge/tests`). Sample exports in `testdata/` are generated by `testdata/make_samples.py`.

Requirements: Python 3.12 and `cryptography`; `boto3` only for KMS signing. Packs are canonicalized with `canon.py` (full RFC 8785). `verify.py`'s own float handling covers integers and simple decimals only, which is all a concierge pack contains (percentages with one or two decimals).
